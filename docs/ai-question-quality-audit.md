хамт унана — тэрийг хүн уншиж үнэлэх ёстой.

## 2. Батлагдсан гэмтлүүд (энэ фазэд зассан)

### 2.1 Провайдерын түүхий JSON хэрэглэгчид харагдана — P1

Бодит дуудлагаар батлагдсан. Түлхүүр хүчингүй үед хэрэглэгч дараахыг хардаг байв:

```
AI үйлчилгээний алдаа: {"error":{"code":400,"message":"API key not valid...
```

- **Файл:** `server/generate.ts` (`generateAiExam` catch)
- **Засвар:** `classifyUpstream()` — API_KEY_INVALID / RESOURCE_EXHAUSTED /
  PERMISSION_DENIED / 404 / SAFETY-г ялгаж, монгол мессеж + код буцаана.
  Түүхий текст хэзээ ч клиент рүү гарахгүй.
- **Тест:** `classifyUpstream` 5 тохиолдол + «raw provider JSON forwarded» тест.

### 2.2 API handler-ийн catch нь алдааны текстийг шууд буцаадаг — P1 (key алдагдах эрсдэл)

`api/exam/generate.ts`-ийн гадаад `catch` нь `err.message.slice(0,120)`-ыг клиент рүү
илгээдэг байв. Google SDK-гийн алдаанд request URL/`key=` орсон бол **түлхүүр
хөтөч рүү** гарна.

- **Засвар:** ерөнхий 500 мессеж + `code:"internal"`. Дотоод деталь хэзээ ч гарахгүй.
- **Батлалт:** 8791 порт дээр бодит Gemini руу хуурамч түлхүүрээр дуудсан →
  `502 {"error":"Серверийн AI түлхүүр хүчингүй...","code":"bad_key"}`;
  хариултад `AIza` = 0, `INVALID_ARGUMENT` = 0.

### 2.3 Уншлага/сонсгол эх текстгүйгээр хүлээн авагдана — P1 (чанар)

Валидатор зөвхөн «асуулт эсвэл эх текст япон байх» гэж шалгадаг байсан тул
`passage: null` уншлагын асуулт хүлээн авагдаж, хариулах боломжгүй асуулт
хэрэглэгчид харагдана.

- **Засвар:** reading/listening-д эх текст заавал, ≥20 тэмдэгт.
  Prompt-д ч «passage is REQUIRED for reading and listening» гэж нэмсэн.
- **Тест:** 4 шинэ тест (хоосон, зай л, хэт богино, хүчинтэй).

### 2.4 Давхардлын `avoid` хэзээ ч илгээгддэггүй байв — P2

`AiRequest.avoid` серверт бүрэн дэмжигдсэн ч клиент илгээдэггүй байсан →
үүсгэх бүрд ижил асуулт давтагдана.

- **Засвар:** `MockExam` нь `aiSeenRef`-д үүссэн асуултуудыг хадгалж,
  `AiExamPanel`-д `avoid` болгон дамжуулна (`slice(-30)`).
- **Батлалт (browser, fetch stub):** 1 дэх дуудлага `{level,section,count}`;
  2 дахь дуудлага `{level,section,count,avoid}` — `avoid` 2 элементтэй.

### 2.5 «Хяналт шаардлагатай» асуултыг «хянасан» гэж шошголдог — P2 (шударга бус шошго)

`needs_review` төлөвтэй асуулт UI дээр «AI үүсгэсэн · хянасан» гэж харагддаг байв.

- **Засвар:** `aiToQuestion` нь `qualityStatus`-оос хамаарч
  «хянасан» эсвэл «хяналт шаардлагатай» гэж шошголно.
- **Тест:** 2 тест (хоёр төлөв).

### 2.6 Мобайл дээр асуултын тооны товч 28px — P3 (хүрэхэд жижиг)

390px өргөнд 5/10/20 товч 28×29px байв.

- **Засвар:** `min-h-9 min-w-9` → 36×36px.
- **Батлалт:** browser дээр хэмжсэн, хэвтээ халилт 0.

## 3. JLPT N2 чанарын шалгах хуудас

Автоматаар шалгагдах (валидатор + `verify:ai`):

| Шалгуур | Төлөв |
|---|---|
| Яг 4 сонголт, ID давхардалгүй | ✅ код |
| Зөв хариулт сонголт дотор, яг нэг | ✅ код |
| Сонголтын текст давхардалгүй (NFKC) | ✅ код |
| Япон текст заавал (асуулт эсвэл эх текст) | ✅ код |
| Placeholder / хоосон текст хориотой | ✅ код |
| Уншлага/сонсголд эх текст | ✅ код (шинэ) |
| Багц дотор ижил асуулт давтахгүй | ✅ код |
| Хүсэлтийн түвшин/хэсэгтэй тохирол | ✅ код (хатуу татгалзана) |
| Монгол тайлбар ≥15 тэмдэгт, зөв хариултыг дурдсан | ✅ код (дурдаагүй бол `needs_review`) |
| `sourceType: "ai_generated"` (албан ёсны гэж шошголох боломжгүй) | ✅ код (сервер тогтооно) |

Хүний үнэлгээ шаардлагатай (дээж байхгүй тул **шалгагдаагүй**):

- Япон хэлний байгалийн байдал, N2-д тохирох хүндрэл
- Сөрөг сонголтууд «боломжтой боловч тодорхой буруу» эсэх
- Хоёр сонголт хоёулаа зөв байх боломж (утга зүйн хоёрдмол байдал)
- Соёлын/нөхцөл байдлын буруу таамаглал
- Тайлбарын япон хэлний зөв байдал

## 4. Prompt-ийн аудит (одоогийн байдал ба дутагдал)

Prompt (`buildPrompt`) аль хэдийн хориглодог: албан ёсны гэж шошголох, placeholder,
давхардсан сонголт/асуулт, `avoid`/`focus` жагсаалт. Шаарддаг: 4 сонголт, нэг зөв,
монгол тайлбар, япон тайлбар.

**Дутагдал (засагдаагүй, эрсдэлд бүртгэсэн):**

1. N2-ийн ханз/дүрмийн **албан ёсны жагсаалтад** нийцүүлэх заавар байхгүй —
   модель N3 эсвэл N1 зүйл хэрэглэж болно. (`data/` дотор түвшин тус бүрийн
   ханз/үг байгаа тул ирээдүйд шүүлт хийх боломжтой.)
2. Сонголт бүрийн **яагаад буруу** гэдгийг тайлбарлах шаардлага байхгүй —
   тайлбар зөвхөн зөвийг тайлбарлана.
3. Ромажи (romaji) хориглоогүй.
4. `passage`-ийн уртын доод хязгаар prompt-д байхгүй (валидатор 20 тэмдэгт).
5. Нэг л temperature (0.9) — олон янз байдал сайн, гэхдээ тогтвортой чанарт
   хортой; `temperature`-ыг хэсэг тус бүрээр өөрчлөх нь туршилт шаардана.

Эдгээр нь **бодит дээжгүйгээр** өөрчлөхөд эрт — Phase 2 дууссаны дараа
дээжийн үр дүнд тулгуурлан тохируулах ёстой.

## 5. «Албан ёсны JLPT» гэж шошголохгүй байдлын батлалт

- Сервер `sourceType: "ai_generated"`-ыг **моделийн хариултаас үл хамааран** тогтооно
  (`validateQuestion`), тестээр хамгаалагдсан (`sourceType: "official_jlpt"` оролдлого
  хүчингүй болдог).
- UI: `MockExam` толгойд «AI үүсгэсэн дасгал — албан ёсны JLPT шалгалт биш»,
  панельд «AI үүсгэсэн асуулт — албан ёсны JLPT асуулт БИШ…» гэсэн байнгын анхааруулга.
- Browser дээр батлагдсан: AI дасгал ачаалахад хоёр шошго хоёулаа харагдана.
