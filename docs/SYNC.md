# SYNC — серверийн гэрээ болон клиентийн merge дүрэм

Сүлжээний синхрончлолын дүрэм. Хэрэгжилт: `src/lib/merge.ts` (цэвэр функц, I/O үгүй),
`src/lib/store.tsx` (`pull()`/`push()`), тест: `src/lib/merge.test.ts`.

## 1. Серверийн гэрээ (`server/` одоогоор байхгүй — энэ нь ТЭМДЭГЛЭЛ, хийх үедээ дагана)

| Мэдээлэл | Мэдээлэл | Хариу |
|---|---|---|
| `GET /api/sync` | — | `200 { rev, updatedAt, doc }` · `401` токенгүй |
| `PUT /api/sync` | `{ rev, doc }` | `200 { rev, updatedAt }` шинэ rev-тэй · **`409 { rev, updatedAt, doc }`** — серверийн rev нь клиентийн илгээсэн rev-тэй таарахгүй (хүснэгтээс татна уу) |

- `rev` нь серверийн тасалбар (monotone counter), **мэдээлэл биш**: `doc` нь бүрэн баримт.
- `409`-ийн хариу ДОРООХ нь серверийн одоогийн баримт (`doc`) — тэгэхээр нэг дуудлаар
  л шинэчилнэ (шүргэх хүсэлт шаардлагагүй).
- Сервер merge **хийдэггүй**: баримтыг шүүгүйгээр хадгална. Бүх merge нь клиентийн
  үүрэг — тиймээс хоёр төхөөрөмж синк хийхэд аль нэг нь баримтаа `mergeDocs`-аар
  дамжуулж илгээнэ.
- Хүчинтэй бус өгөгдөл (JSON биш, schema зөрсөн) серверээс ирвээс **мэдээллийг хадгална**,
  зөвхөн анхааруулга харуулаад local-ыг үлдээнэ (доор §4).

## 2. Doc-ийн талбар → merge дүрэм

| Талбар | Дүрэм | Яагаад |
|---|---|---|
| `profile` (тохиргоо) | **тал бүрээр** LWW: `profileTs[field]` илүү их талбарын утгыг авна. Тэгш бол JSON-ийн тэмдэгтээр жишиж тогтооно (эгчилж зэргэлзэхгүй) | Дэлгэц хоёрын тохиргоо тусдаа өөрчлөгдөнө; нэг бүтэн JSON-оор LWW хийвэл нэг төхөөрөмжийн бүх тохиргоо устана |
| `srs` (карт) | карт бүрээр: `last` (сүүлийн давталт) илүү их; тэгш бол `n` их; тэгш бол JSON тэмдэгтээр. `h` (үнэлгээний түүх) — илүү их `last`-тай талынх | Гол ажил (`st/df/n/l/due/ph`) сүүлийн давталтаар тодорхой |
| `srs[].h` түүх | **Хожсон талын түүх** (union биш) | `h` нь зөвхөн `number[]` (зураглал: үнэлгээ), **цагийн мөр алга** → давхардуулж ялгах боломжгүй. Нөгөө талын дүнг `n/l`-д max-аар авдаг тул ажил алдахгүй |
| `xp` | **Төхөөрөмж бүрийн хувь нэмрийн газар** `xpParts[deviceId]`, нэгтгэн дүнг нэмнэ. Хуучин (partsгүй) баримт = `legacy` гэсэн түлхүүр, хоёр талын хуучин дүнг max авна | max авбал ажил алдана (ажлын хугацаанд олсон XP унах), нэмбэл нэг үйлдэл хоёр удаа тоологдоно |
| `activity` (өдөр бүрийн) | өдрийн **жагсаалтыг нэгтгэнэ** (streak-ийг үүнээс гаргана); өдөр бүрийн тоог `activity[day].parts`-аар нэмнэ, partsгүй бол max | Streak нь хоногийн тооноос биш өдрийн **байгаагаас** хамаарна |
| `achievements` | нэгтгэх, олдсон **цагийг хамгийн эрт** авна | анхны амжилт нь чухал, устгах утга биш |
| `favorites` / `grammarDone` / `readingDone` / `listeningDone` | **нэгдсэн** (set union), `tomb`-д байгааг хасна | жагсаалт → зөвхөн байх/байхгүй |
| `mistakes` | id-гаар нэгдсэн; давхардсан бол `at` илүү их; `count` = max (давтан тоолохгүй) | Нэг алдаа хоёр төхөөрөмж дээр буруу бичигдсэн ч нэг л тоологдоно |
| `writing` | `best` = max, `tries` = max, `at` = max | шилдэг оноо болон сүүлийн оролдлого |
| `mnemonics` | хоосон бус; хоёулаа байвал урт бөгөөд тэмдэгтээр жишиж тогтооно | хувь хүний тэмдэглэл, устгахаас илүүтэй нь үлдэнэ |
| `exams` / `quizzes` | `at` (эсвэл дээд түвшний id)-гаар нэгдсэн, хугацаагаар эрэмбэлнэ | нэг шалгалтыг хоёр удаа тооцохгүй |
| `kanaBest` | max | шилдэг оноо |
| `placement` | `at` илүү ихийнх | хамгийн сүүлийн тогтоолт |
| `curriculum` | `done` хоног бүрээр нэгдсэн (`at` max); эхлэл `startedAt` илүү их | төлөвлөгөөний явц нэмэгдэнэ |
| `createdAt` | **min** (хамгийн эрт) | анх эхэлсэн хугацаа |
| `updatedAt` | max (доод заагаас дээшгүй) | баримтын хамгийн сүүлийн шинэчлэл |
| `tomb` (шинэ) | нэгдсэн, тэмдэгтээр тогтооно | **устгасан зүйл дахин сэргэхгүй** |
| `v` | 3 | хувилбарын шилжүүлэлт `storage.ts`-д |

### Цагийн зөрүү (clock skew)

- Тэмдэгт цаг `now + 24 цагаас` хойш бол **`now`-т шахна** (ажиллах төхөөрөмжийн цаг буруу).
- Сэтгүүлч биш цагууд (`last`, `at`, `due`, `startedAt`, `createdAt`) ч мөн адил шахна.
- **Тэгш зэрэгцээ тэмдэгт**: заавал симметрик байх ёстой (merge(a,b) = merge(b,a)) —
  JSON-ийн тэмдэгт дарааллаар илүү ихийг сонгоно.

## 3. Sync урсгал (клиент)

```
pull():
  remote = GET /api/sync
  if remote.rev <= rev → дууссан
  snapshotLocal(backup)                     # sync-ээс ӨМНӨ нөөц (сүүлийн 3 үлдэнэ)
  merged = mergeDocs(local, validate(remote))
  setDoc(merged)  → local write (алдаа үед бичихгүй, зөвхөн уншна)
  push(merged, remote.rev)

push():
  if 409 → pull-and-merge-ээр дахин (3 удаа, 300мс → 600мс → 1.2с)
  бүтэлгүйтвэл dirty=true үлдэнэ, local data хэзээ ч устгахгүй
```

- `pull → push` слеп `push(true)` байсан → одоо **зөвхөн merge-ийн үр дүнг** илгээнэ.
- Хэсэгчилсэн бүтэлгүйтсэн sync-ээр local баримт **цэвэрлэгдэхгүй**.

## 4. Алдааны горим

| Нөхцөл | Үйлдэл |
|---|---|
| Сервер холбогдохгүй | dirty=үлдэнэ, backoff (30с→10мин), чимээгүй; локал ажил хэвийн |
| `409 conflict` | re-pull + re-merge, дараа шинэ rev-тэй push (3 оролдлого) |
| Одооны резерв (quota) | toast + нөөц хадгална, merge үргэлжлүүлнэ |
| Хүчинтэй бус remote (`doc` JSON биш) | local-ыг хадгална, `syncRemoteCorrupt` мэдэгдэл, серверийн утгыг **дараагийн push-ээр дарж бичнэ** (бичлэг алдаатай байгаа тул) |
| Одоо локал эвдэрсэн | `storage.ts` нөөцөлж сэргээнэ → дараа нь merge |

## 5. Тэмдэглэл / хязгаарлалт

- `Device ID`: `localStorage["nd:device"]` (үгүй бол үүсгэнэ) — merge-ийн хувь нэмрийн түлхүүр.
- `xpParts`/`activity[].parts`/`profileTs`/`tomb` нь **нэмэлт, сонголттой** талбарууд:
  хуучин баримт ч merge хийгдэнэ (хэвийн горим).
- Давтан sync ижил баримттай → merge **идемпотент** (property тест 500+ тохиолдол).
- Бодит олон төхөөрөмжийн бодит сервер тест **хийгдээгүй** (`server/` байхгүй).
